GbaC0re v1.2.16 -- PAYLOAD SWAP TEST
====================================

New: SWAP PAYLOAD in the pause menu (before QUIT, which stays last).

The PS5 JIT pool is one-way per process (proven 2026-09-28: munmap+close does
not recover it). So a swapped payload REUSES the existing JIT mappings: the
new blob is memcpy'd over the old one in place, no new JIT allocation.

Test 1 -- reload GbaC0re without relaunching the game:
1. Fresh game launch, upload as normal:
     python gba_launcher.py 192.168.0.140 --roms <romdir>
2. Boot a ROM, open pause menu, select SWAP PAYLOAD.
3. UDP log should show:
     menu: swap payload requested
     Done. status=1 step=99 ...
     Swap requested: waiting for replacement payload blob
4. From your PC, send the blob only (no Lua re-upload):
     python gba_launcher.py 192.168.0.140 --blob gba_emu.bin --blob-only
5. Log should show:
     Swap: 715680 bytes written into existing mapping(s) ...
     === GbaC0re v1.2.16   (banner from the fresh _start)
   PASS: the ROM picker appears, no game relaunch needed.
   FAIL: send the full UDP log.

Test 2 -- repeat: SWAP again and re-send. Each swap leaks the old payload's
anonymous .data mapping (~1.3MB regular VM, not JIT pool), so a handful of
swaps is fine; dozens might exhaust VM (game relaunch recovers).

Test 3 -- QUIT still works: status=0, script ends, teardown runs (best-effort).

Constraint: the replacement blob must fit in the 0xB0000 (704KB) reserve.
A larger blob logs "Swap blob too large" and ends the script.
