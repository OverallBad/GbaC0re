GbaC0re v1.2.15 + JIT teardown test
====================================

What changed: lua/gba.lua now frees the JIT shared-memory mappings after
the payload exits cleanly (munmap + close on all handles). The payload blob
(gba_emu.bin) is unchanged from v1.2.15 stable.

Test procedure:
1. Fresh-launch the game (SWRR), run the exploit as normal.
2. Upload this build, boot a ROM, play briefly.
3. QUIT from the pause menu (clean exit -- you should see "Done. status=0").
4. Watch the UDP log for:
     JIT: freed mapping 1/3 ...
     JIT: freed mapping 2/3 ...
     JIT: freed mapping 3/3 ...
     JIT: teardown complete -- pool should be clean for next upload
5. Upload a second payload WITHOUT relaunching the game.
6. Check whether the second run's JIT creation succeeds:
     PASS: "JIT: blob ... -> 3 mapping(s)" then "Code: ... bytes written"
     FAIL: "JIT FAIL at CreateSharedMemory ... 0x8002000C"

If FAIL: the pool is truly one-way (only a game relaunch recovers).
         Send the full UDP log -- the munmap return codes will tell us why.
If PASS: relaunch-without-quitting-the-game now works. Try a third upload
         too, to confirm it's repeatable.
